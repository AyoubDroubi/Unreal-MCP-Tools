Redirector Cleanup / Fix Up Redirectors

Repairs references left behind when assets are moved or renamed and removes obsolete redirector objects.

Why it helps

  • Prevents stale asset paths accumulating
  • Makes large refactors safer
  • Can run interactively or through ResavePackages commandlet
  • Keeps Content folders and automation predictable

Codex / MCP role

Codex may prepare and run a controlled commandlet workflow, but must inspect git status and never mass-resave the project silently.

Recommended workflow

  1. After a controlled asset move/rename, inspect redirectors.
  2. Use Fixup Redirectors in the Content Browser for local work.
  3. For project-wide maintenance, use the ResavePackages commandlet with FixupRedirectors in a clean branch.
  4. Validate references and commit all resulting asset changes together.
Watch out: Project-wide fixup can touch many binary assets. Run on a clean branch/worktree and review the resulting source-control diff.

Adoption decision

Must adopt. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
