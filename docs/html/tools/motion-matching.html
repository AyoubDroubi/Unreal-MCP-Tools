Motion Matching / Pose Search

Query-driven pose selection from animation databases as an alternative to large hand-authored locomotion state machines.

Why it helps

  • Responsive locomotion
  • Less transition-graph authoring
  • Scales by adding quality animation data
  • Includes tuning/debug tooling

Codex / MCP role

Use as a deliberate animation architecture, not an automatic replacement for every state machine.

Recommended workflow

  1. Enable Pose Search.
  2. Define a schema and pose database.
  3. Feed movement/query features.
  4. Tune cost weights with representative gameplay.
  5. Profile database/query cost and debug selections.
Watch out: Quality depends heavily on animation coverage/data preparation; a sparse database will not be rescued by code.

Adoption decision

Evaluate for high-fidelity locomotion. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
