Git LFS + File Locking Workflow

Store .uasset/.umap in Git LFS and lock binary assets that cannot be merged safely.

Why it helps

  • Keeps Git repository healthy
  • Prevents simultaneous binary edits
  • Fits Azure Repos/Git workflows
  • Makes asset ownership explicit

Codex / MCP role

Before mutating a binary asset, verify repository cleanliness and lock/ownership policy; never auto-force conflicts.

Recommended workflow

  1. Track .uasset/.umap with LFS.
  2. Mark them lockable.
  3. Lock before edit.
  4. Pull/rebase before work.
  5. Unlock after successful push.
  6. Never attempt text merges of binary assets.
Watch out: LFS alone does not prevent merge conflicts; locking discipline matters.

Adoption decision

Must adopt with Git/Azure. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
