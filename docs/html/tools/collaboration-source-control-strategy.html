Unreal Collaboration Strategy: Git LFS + Locks + Short-Lived Branches

A practical team policy for binary Unreal content: LFS storage, explicit locks for non-mergeable assets, small branches and frequent synchronization.

Why it helps

  • Reduces conflicting .uasset/.umap edits
  • Keeps binary history out of normal Git object storage
  • Makes ownership of currently edited assets visible
  • Encourages smaller, reviewable changes

Codex / MCP role

Before modifying binary assets, Codex should inspect source-control status/locks and avoid parallel edits to the same asset.

Recommended workflow

  1. Track Unreal binary assets with Git LFS before adding them.
  2. Lock high-conflict binary assets before editing.
  3. Pull/rebase before starting significant asset work.
  4. Keep branches/tasks narrow and integrate frequently.
  5. Never resolve a binary merge by guessing; choose one asset revision or merge using Unreal-aware tooling when supported.
Watch out: LFS does not make binary assets mergeable. Coordination and locking remain necessary.

Adoption decision

Must adopt with Git. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
