Gameplay Ability System (GAS)

Framework for abilities, attributes, effects, cues, costs, cooldowns, replication and prediction.

Why it helps

  • Scalable combat/ability architecture
  • Built-in replication/prediction
  • Data-driven effects
  • Reusable ability tasks

Codex / MCP role

When the game has substantial combat/abilities, prefer GAS over custom one-off cooldown/buff systems.

Recommended workflow

  1. Put ASC ownership in the correct Actor/PlayerState.
  2. Define Attribute Sets.
  3. Use Gameplay Effects for modifications.
  4. Use Gameplay Tags for conditions/state.
  5. Keep abilities focused and composable.
Watch out: GAS has a learning/architecture cost; do not add it to a tiny prototype without need.

Adoption decision

High for combat/RPG/multiplayer. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
