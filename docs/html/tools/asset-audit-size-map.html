Asset Audit + Size Map

Built-in asset footprint and dependency-size inspection for identifying oversized content and expensive dependency trees.

Why it helps

  • Find unexpectedly large assets
  • See dependency size visually
  • Export Asset Audit data for analysis
  • Catch package/cook footprint problems before release

Codex / MCP role

A future MCP wrapper can export audit data to structured JSON/CSV so Codex can rank size regressions automatically.

Recommended workflow

  1. Enable AssetManagerEditor when required.
  2. Open Size Map from an asset/folder or Reference Viewer.
  3. Open Audit Assets for detailed asset information.
  4. Prioritize the largest unexpected dependencies and verify again after optimization.
Watch out: Editor Size Map is an approximation of asset footprint; packaged/cooked size can differ due to compression and cooking.

Adoption decision

High. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
