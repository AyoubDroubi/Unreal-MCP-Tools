Structured Unreal Logging Strategy

Use project-specific log categories, appropriate verbosity and structured UE_LOGFMT messages so bugs are searchable instead of buried in LogTemp spam.

Why it helps

  • Searchable subsystem logs
  • Runtime verbosity control
  • Commandlet errors integrate with CI
  • Structured fields are easier for Codex to interpret

Codex / MCP role

Logs should include stable identifiers/state needed for diagnosis; Codex can then search logs deterministically without parsing arbitrary on-screen text.

Recommended workflow

  1. Create one category per meaningful subsystem/domain.
  2. Use Error/Warning only for actionable problems.
  3. Use Log/Verbose for normal diagnostic detail.
  4. Prefer UE_LOGFMT for structured messages where useful.
  5. Allow verbosity overrides via -LogCmds during debugging.
Watch out: Never log secrets/tokens/PII, and avoid per-frame spam in normal verbosity levels.

Adoption decision

Must adopt. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
