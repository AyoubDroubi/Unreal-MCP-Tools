C++ / Blueprint Boundary Strategy

Keep stable/high-performance/framework code in C++ and fast content/gameplay iteration in Blueprints.

Why it helps

  • Faster iteration without Blueprint monoliths
  • Strong reusable APIs
  • Performance where needed
  • Designer-friendly extension

Codex / MCP role

Codex should choose the lane deliberately instead of converting everything to C++ or leaving everything in Blueprint.

Recommended workflow

  1. Put stable primitives/components/subsystems in C++.
  2. Expose narrow Blueprint APIs.
  3. Keep tuning/content assembly in Blueprint/Data Assets.
  4. Move hotspots or fragile duplicated logic to C++ only when justified.
Watch out: Avoid blueprint-only private engine reimplementations and avoid C++ for every tiny designer-tuned behavior.

Adoption decision

Must adopt. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
