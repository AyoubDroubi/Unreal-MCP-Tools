Data Registries

Global read-only data access layer that can combine tables/curves and support caching/async access.

Why it helps

  • Centralized data access
  • Data-driven gameplay
  • Multiple data sources
  • Useful for large configurable catalogs

Codex / MCP role

Useful when building scalable item/config/stat catalogs without hard-coding data in Blueprints.

Recommended workflow

  1. Use for shared read-only structured gameplay data.
  2. Define registry types and sources.
  3. Keep session/player mutable state elsewhere.
  4. Validate row identifiers and schemas.
Watch out: Not a replacement for SaveGame/session state.
