Gameplay Tags

Hierarchical identifiers for gameplay state, categories, abilities, effects and cross-system queries.

Why it helps

  • Avoid string/enumeration sprawl
  • Works with GAS and other systems
  • Data-driven queries
  • Great decoupling primitive

Codex / MCP role

Prefer Gameplay Tags when multiple systems need a shared semantic vocabulary.

Recommended workflow

  1. Define a naming hierarchy.
  2. Use tags for semantic state/categories, not arbitrary data.
  3. Centralize native/common tags.
  4. Validate references and avoid near-duplicate meanings.
Watch out: Tags can become an ungoverned global namespace; maintain conventions.

Adoption decision

Must adopt for scalable gameplay. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
