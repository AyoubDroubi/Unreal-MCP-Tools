Virtual Assets

Separates bulky asset payload data from lightweight package metadata so source-control syncs can become much smaller.

Why it helps

  • Reduces workstation disk usage
  • Can shorten source-control sync time for large projects
  • Downloads heavy payloads on demand
  • Pairs with shared DDC infrastructure

Codex / MCP role

Treat as infrastructure configuration, not a per-asset mutation trick. Codex can audit configuration and rollout scripts.

Recommended workflow

  1. Measure whether source-control payload size is a real bottleneck.
  2. Review backend/source-control requirements.
  3. Configure shared DDC/virtualization on a test project first.
  4. Virtualize supported assets and measure sync/editor behavior before team rollout.
Watch out: The documented quickstart assumes specific source-control/DDC infrastructure; do not enable blindly for a small Git project.

Adoption decision

Evaluate for large teams. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
