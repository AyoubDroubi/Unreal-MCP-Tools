Replication Graph

Persistent replication-list graph that scales server relevancy work for large numbers of Actors and clients.

Why it helps

  • Reduces per-connection actor relevancy cost
  • Custom spatial/semantic replication nodes
  • Proven large-scale design
  • Good bridge when generic replication becomes CPU-bound

Codex / MCP role

Use only after profiling shows replication-list generation is a bottleneck; Codex can help implement/test custom nodes.

Recommended workflow

  1. Profile server replication cost first.
  2. Group actors by spatial/semantic behavior.
  3. Configure a custom Replication Driver.
  4. Create focused custom nodes only where needed.
  5. Measure CPU/bandwidth with representative clients.
Watch out: Adds networking architecture complexity and the plugin is marked Beta; splitscreen limitations are documented.

Adoption decision

High for many replicated actors/connections. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
