Azure DevOps CI for Unreal

Use an Azure Pipelines self-hosted build machine with Unreal installed to run validation, UBT/UAT, cook, package and test jobs.

Why it helps

  • Keeps the Unreal build environment under your control
  • Machine-level engine/cache state persists across jobs
  • Fits Azure Repos and branch policies
  • Can publish packaged builds/test artifacts automatically

Codex / MCP role

Codex can author/maintain azure-pipelines.yml and project build scripts, while engine credentials/signing secrets stay in secure variables.

Recommended workflow

  1. Provision a dedicated self-hosted Windows agent with the exact Unreal version/toolchain.
  2. Checkout Git LFS correctly.
  3. Run lightweight validation first, then UBT/UAT build/cook/test stages.
  4. Cache/use shared DDC where appropriate.
  5. Publish logs, test reports and packaged artifacts; gate protected branches on required jobs.
Watch out: Microsoft-hosted agents are usually a poor fit for large Unreal builds because the engine/toolchain/cache is heavy; prefer self-hosted agents for repeatable production builds.

Adoption decision

High when Azure hosts the game repo. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
