One File Per Actor (OFPA)

Stores level Actor instance data in external files so different team members can modify different Actors without constantly touching the main level file.

Why it helps

  • Reduces source-control contention on large levels
  • Enabled by default with World Partition
  • Makes parallel world editing more practical
  • Cooked builds still embed Actors normally

Codex / MCP role

When editing level actors, Codex should understand OFPA-generated files as engine-owned content and avoid renaming/manipulating them directly on disk.

Recommended workflow

  1. Use World Partition or enable OFPA for the target level.
  2. Keep actor edits scoped and review source-control changes carefully.
  3. Use locks/source-control discipline for assets that remain indivisible.
  4. Validate level load/cook after large structural changes.
Watch out: OFPA helps actor-level contention but does not make arbitrary .uasset files mergeable.

Adoption decision

High for shared levels. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
