Blueprint Architecture: Components, Interfaces, Dispatchers & Subsystems

Use composition and explicit contracts to prevent giant, tightly-coupled Blueprint classes.

Why it helps

  • Smaller Blueprints
  • Less casting
  • Reusable systems
  • Clear ownership
  • Better AI-edit safety

Codex / MCP role

Default architecture rules for generated Blueprint systems; refactor before graphs become giant.

Recommended workflow

  1. Put reusable actor behavior in Actor Components.
  2. Use Blueprint Interfaces for capability contracts.
  3. Use Event Dispatchers for one-to-many notifications.
  4. Use Subsystems for scoped services.
  5. Keep widgets as presentation, not game-state owners.
Watch out: Do not replace every direct reference with an interface/event; choose the simplest decoupling that fits ownership.

Adoption decision

Must adopt. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
