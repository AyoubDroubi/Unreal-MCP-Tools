method 5.x Workflow
Must adopt before releases

Clean Build / Cook / Package Verification

Regularly validate the project outside the warm developer editor: clean build, cook and package.

Why it helps

  • Catches hidden local-state dependencies
  • Finds missing asset references
  • Verifies shipping configuration
  • Prevents last-minute packaging surprises

Codex / MCP role

A task is not release-ready merely because PIE works; Codex should report clean build/cook/package status separately.

Recommended workflow

  1. Run clean Editor build periodically.
  2. Cook target platforms.
  3. Package Development/Shipping candidates.
  4. Launch packaged build.
  5. Run smoke/automation tests.
Watch out: Live Coding success is insufficient evidence for release readiness.

Adoption decision

Must adopt before releases. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
