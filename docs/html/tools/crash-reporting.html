Crash Reporter + Crash Context

Captures crash IDs, call stacks, logs, system data and custom game context, with support for routing packaged-game reports to your own backend/service.

Why it helps

  • Actionable crashes from testers/users
  • Logs and call stacks together
  • Custom game-state context
  • Supports packaged builds

Codex / MCP role

Codex can analyze symbolicated call stacks/logs and correlate them with source changes; never send secrets/PII as crash context.

Recommended workflow

  1. Include Crash Reporter in test/release packages.
  2. Route reports to an approved service/backend.
  3. Upload matching symbols securely.
  4. Add compact custom context such as map/mode/build/session.
  5. Triage recurring signatures and link fixes to build versions.
Watch out: Packaged builds need explicit Crash Reporter configuration; protect user privacy and keep symbols/build IDs organized.

Adoption decision

Must adopt before external testing. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
