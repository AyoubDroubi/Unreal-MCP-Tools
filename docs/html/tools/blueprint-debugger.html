Blueprint Debugger

Pauses Blueprint execution in PIE/SIE with breakpoints, watches, call stacks and step controls.

Why it helps

  • Inspect runtime pin and variable values
  • Step through visual execution instead of guessing
  • See breakpoints, watches and execution trace in one place
  • Debug a specific Blueprint instance in PIE

Codex / MCP role

Codex should use MCP-readable state/logging when available, while this remains the human runtime truth tool for complex visual execution bugs.

Recommended workflow

  1. Select the Blueprint instance in Debug Object.
  2. Place a breakpoint on the suspicious node.
  3. Run PIE/SIE and reproduce the issue.
  4. Inspect watches/pins and step through execution.
  5. Fix the graph, compile, and reproduce again.
Watch out: Pin values are only meaningful after the relevant nodes have executed.

Adoption decision

Must adopt. Treat this page as a project decision guide; confirm engine version, license, team scale and project constraints before adoption.
